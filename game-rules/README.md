# Player rule guides

These Markdown guides explain one part of the game at a time. They can be adapted
for onboarding, contextual help and an in-game rules library.

## Editing convention

- Keep each topic in its own file with a stable filename and descriptive headings.
- Use plain, player-facing language for confirmed rules. Keep sections short enough
  to reuse individually in contextual help.
- Include `status` metadata: `planned` or `playable`. A confirmed design is not
  necessarily implemented.
- Keep proposals and unresolved decisions in a clearly marked editorial section.
  Do not display that section to players or advertise planned guides as playable.
- Update the guide when a rule changes; avoid duplicating the same rule in several
  guides. Link to related topics instead.
- Keep the root [game-rules.md](../game-rules.md) aligned as the consolidated
  reference for implemented behaviour. These guides will grow topic by topic;
  this folder does not replace that reference yet.

These files are documentation only. No automatic publishing or in-game rendering
is connected yet.
